# AIC v0.2.12-aic.4 (prerelease)

修正 aic.3 拔屏后进入独立 Openbox 空桌面的问题。默认在原 Xorg 会话内补虚拟输出，保留原 Ubuntu 桌面、窗口和应用进程。

## 安装前提

Ubuntu 18.04 使用本发布的 `x86_64-ubuntu18.04.tar.gz`。Intel 核显需要预先配置 Xorg Intel DDX `VirtualHeads`，具体步骤和可撤销安装脚本见包内 [SAME_SESSION.md](../../contrib/virtual-desktop/SAME_SESSION.md)。首次配置需要重启图形会话，会关闭当时的窗口；配置完成后的拔屏补屏在原会话内完成。没有可用虚拟输出时明确报错，保留原会话，不另开空桌面。

无屏冷启动仍要求 GDM 启动原来的 Xorg 用户桌面，并给主机正确的 DISPLAY/XAUTHORITY。linger 只能启动用户服务，不能替代图形登录。该配置不自动修改 GDM、自动登录或小车。

## 行为

- 无物理显示器时，经过两次连接状态确认后启用原会话的虚拟输出，默认 1920×1080，可用 `UU_VIRTUAL_SIZE` 指定。
- 观看时才编码传输；停止观看、重新插屏、停止主机都保留同会话虚拟输出和应用。补屏时已连接的桌面控制端需要重新连接。
- 原窗口和本机终端视图留在原 Xorg，不迁移、不重启应用或 PTY；独立工具连接保留。
- `UU_AUTO_VIRTUAL_DISPLAY=0` 关闭补屏；`UU_VIRTUAL_DISPLAY_MODE=xvfb` 显式保留旧的独立软件桌面用途。
- 不把锁屏、DPMS 熄屏或未知连接状态当作拔屏。Wayland/Portal/KMS/none 后端不启用该功能。

## 验证范围

GitHub CI 在 Ubuntu 18.04 构建及运行真实 Xorg dummy 双输出和完整桌面，检查原 Xorg、root window、应用 PID 和窗口 ID 在断屏、两次按需捕获、重新插屏与主机退出后保持一致；另检查无屏启动和空闲无 FFmpeg 编码器。旧 Xvfb 流程作为显式模式继续验证。其余默认、viewer、Wayland/Portal、inproc-av 和 macOS 检查保留。

dummy 输出与合成连接状态用于验证主机控制逻辑，不能证明 Intel VirtualHeads 的实际硬件行为、GNOME/GDM 无屏冷启动或官方客户端效果；这些仍需目标机实测。本发布不会自动更新小车。
